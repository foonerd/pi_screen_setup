# Changelog

All notable changes to Pi Screen Setup are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html). The presets database (`display_presets.json`) carries its own version and is updated on players independently of the plugin.

## [Unreleased]

### Added

- `lib/board.js`: the board is read from the revision code the firmware publishes (`/proc/device-tree/system/linux,revision`, else `/proc/cpuinfo`), decoded against the documented type, processor and memory fields. Pi Zero 2 W, Pi 400, Pi 500, CM4S, CM5 and CM5 Lite are now recognised as themselves; installed memory is exact instead of rounded from `MemTotal`.
- `lib/configtxt.js`: a reader for `config.txt` and its includes that applies the firmware's conditional-filter rules (`[all]`, `[none]`, model filters, `[board-type=]`, serial `[0x…]`, `[EDID=]`, `[gpioN=]`, `[HDMI:n]`, `[tryboot]`, expression filters; same type replaces, different types combine, state carries across `include`) and reports what actually applies to this board. Tests cover Volumio's 4.119 and 4.231 `volumioconfig.txt`: the 4.231 file leaves KMS unapplied on every Pi 3, 4 and 5 because its `[0x9020e0]`/`[0x9020e1]` serial filters precede the model filters.
- `lib/verify.js`: what the running system shows — whether the vc4 driver is bound, the DRM connectors and their state, the CMA in use, the kernel command line — and a diagnostics report built from that, the boot files as found and as they apply to the board, the plugin's settings and the display-related kernel messages. The hardware section gets a "Write a diagnostics report" button (`/tmp/pi-screen-setup-diagnostics.txt`) and a line stating what the boot files apply to this board right now.
- When the plugin is enabled but not yet configured and the boot files apply no display driver (KMS) on a board that has one, the plugin writes the one driver line itself under its own banner and says so (reversible, replaced by the wizard's file).
- `lib/recover.js` and the "settings rebuilt" path: when the settings file holds nothing applied but the boot files carry the plugin's own configuration (a settings file reset or restored from an older backup, a file written by a release that could not persist, an OS update followed by "restore settings"), the settings are read back from `videoconfig.txt`, `cmdline.txt` and the saved metadata — output, preset, rotation, HDMI mode, KMS and CMA — stored, and announced with the date the files were written. A baseline file is never mistaken for a configuration; a wizard the user reset stays reset.
- `lib/conf.js`: the settings file in the shape v-conf reads (`{ type, value }` leaves). Files written by earlier releases are converted once on start, keeping their values; the static check refuses a shipped `config.json` in any other shape.
- `lib/privileged.js`: the boot-partition writer (`sudo cp`/`chmod`/`rm` as a vector of arguments, never a shell string); a relocated root writes directly.
- `test/e2e.test.js` with `test/harness.js`: the plugin end to end in a Volumio-shaped tree — the settings file as Volumio seeds it, the real v-conf, real 4.231 boot files, a board through `/proc` and `/sys`, the wizard, the apply, a restart, the recovery, an OS update, the migration of a hand-written configuration, restore points, the presets database over HTTP, the admin draft, the management API. Every output type is written, the settings reset, recovered and regenerated to the same file. The last test fails if any function of `index.js` was not called. `PI_SCREEN_SETUP_ROOT` relocates every system path for this.
- One root helper, `/usr/local/bin/pi-screen-setup-root` (`plugin/scripts/pi-screen-setup-root.sh`), installed by `install.sh` and the only command the plugin's sudoers entry names. Fixed verbs: `write-boot <name>` (the five boot files by name, from stdin, through a temporary file and a rename, never empty, capped), `remove-boot videoconfig`, `clean-exit`, `install-overlay`/`remove-overlay`/`install-edid` under a `pss-` prefix. The twelve `cp`/`chmod`/`rm` grants of earlier releases are gone, and so is every shell string: `lib/privileged.js` passes an argument vector and the content on stdin.
- `lib/strip.js`: the display lines out of `volumioconfig.txt` (and `userconfig.txt` at a migration) with a record — the original file and the digest of what was left — under `/data/INTERNAL/pi_screen_setup/strip/`. The same set of lines drives the wizard's migration offer, the strip after a Volumio update and the detection in `install.sh`.
- "Remove the plugin's display configuration" (the former "Restore factory defaults") and the uninstall now do the same thing, through the helper's `clean-exit`: the include line leaves `config.txt`, `videoconfig.txt` goes, the rotation parameters leave `cmdline.txt`, and the lines removed from Volumio's files go back when those files are still as the plugin left them; a file edited since is left alone and named. The copies taken at install are no longer written back: after a Volumio update they describe an older system.
- `lib/drift.js`: a difference in the boot files is called a Volumio update when `VOLUMIO_VERSION` moved since the apply (the reference copies now record it), and the notice says so with the version; lines in `userconfig.txt` that act on the display (the Touch Display plugin's `display_lcd_rotate`, a second KMS line, a panel overlay, an `hdmi_` setting) are listed in the hardware section and the diagnostics report.
- `lib/cma.js`: graphics memory (CMA) per board. "Kernel default" is a choice (no `cma-` parameter: 256 MB on Pi 2/3, 508 MB on Pi 4, 64 MB on Pi 5), 512 MB boards are held to 128 MB as Volumio intends for the 3A+, sizes above a board's limit are not offered, custom values are 4 MB aligned. The KMS step shows the board, the CMA in use now (from `/proc/meminfo`) and the one that applies after the next reboot.

### Changed

- Display presets database 1.6.0 (the file deployed players fetch from the repository; same fields as before). Corrected in place, with the vendor page in the notes: Waveshare 5" DSI LCD (C) is 1024x600 on the `7_0_inchC` token and the 5" DSI LCD (D) is 720x1280 on `5_0_inch` (both were listed as 800x480 on the official 7-inch overlay, which cannot drive them); the Waveshare 7" DSI LCD (C) needs `,i2c1` for its touch; the Hosyond 10.1" HDMI Display-H carries the vendor's `hdmi_timings`. Added with the vendor's own lines: Raspberry Pi Touch Display 2 10", twelve Waveshare HDMI panels (3.2" H, 3.4" round, 3.5" 480x800, 5DP-CAPLCD, 8"/9.7" 768x1024, 8" 1536x2048, 9HP/10.1HP-CAPQLED and -B, 10.1EP-CAPLCD, 10.4HP-CAPQLED, 11.6" 1768x828, 12.3" 1920x720), Elecrow Screen-D 7" and SF101C 10.1", Luckfox 7" HD, and the in-tree DPI panels Adafruit Kippah 7", Geekworm MZP280 and Innolux AT056TN53. Same-vendor products that share a row's lines are named in that row's description until the database carries aliases.
- The KMS driver line is written with the board's own overlay and the chosen CMA; on a Pi 5 the second DSI port is named `DSI-2` as the kernel does. `videoconfig.txt` now opens with `[all]`, so a conditional filter left open by the file before it cannot capture its lines.
- Boot validation evaluates what the boot files apply to this board (not whether a line is present somewhere): a configured display driver that the files do not actually apply, or one applied when none is configured, is drift. After drift the files are regenerated from the current settings; the previous behaviour copied back the copies taken at install, which after a system update were stale.
- Backups, restore points, the reference copies, the strip record and the presets cache (the draft, the fetched database, the preset backups and exports) live under `/data/INTERNAL/pi_screen_setup/` instead of the plugin folder, which a plugin update replaces and an uninstall removes. A cache found in the old place at the first start is carried over once. Presets authored on a release before 1.0 must be exported before Volumio's update, which deletes the old folder before the new release runs.
- `test/db-keys.json` and `scripts/db-snapshot.js`: the static check refuses a database in which any key of an earlier release is missing or has another type; new keys must be added to the snapshot on purpose.
- `install.sh` and `uninstall.sh` are POSIX-clean (Volumio runs them with `sh`), install only the helper and its one sudoers line, and keep the Internal Storage directory on uninstall.
- New installs start with the CMA at "Kernel default".
- Installs that still carried the old "Default (64 MB)" CMA setting are moved once to "Kernel default", with a notice; explicit choices are left alone.

### Fixed

- Settings were never persisted. The shipped `config.json` was plain JSON; Volumio copies it verbatim and v-conf reads such a file as empty — every `get` returned undefined (never the default) and every write to an existing key was dropped. The wizard worked from an in-memory cache for one session; after a restart the plugin knew nothing, flipped "configured" on from the presence of its banner, and would have regenerated the boot files from defaults (HDMI0, auto) on the first drift. Found on the bench after an OS update. The file is now shipped and converted in the v-conf shape, and the real settings are recovered from the boot files (above).
- "Custom HDMI Timings" wrote nothing: the database entry `custom-hdmi` has an empty `config`, which the generator took as a preset with no lines; the custom timings and parameters were ignored, and the wizard hid the fields for that choice. Both now treat `custom-hdmi` and `custom` alike.
- `config_hdmi_boost` and `max_framebuffer_*` lines, which the plugin itself writes, are now part of the set it migrates out of and strips from the OS files.
- A migration accepted as-is now saves the reference copies, so an OS update afterwards is detected and the migrated file is put back (it has no settings to regenerate from); restoring the configuration refuses when nothing has been applied yet; a factory restore requires the factory files, not just their directory; the "Auto Detect" entry appeared twice in the HDMI preset list; the KMS baseline reports its effect only once the include is in place.
- The preset count shown in the database section, the manager's API and the update notices counted the database's section markers as presets (250 for 216).
- Editing a preset (preset editor or the Volumio UI) no longer discards the fields the form does not show (`native_resolution`, `recommended_rotation`, `overlay_rotation_param`, `vc4_kms`, `emit_dsi_overlay`, `notes`, …); a saved preset keeps everything it had.
- The repository is laid out as `plugin/` (what ships), `test/` (the static check and the module tests), `scripts/` (packaging, release notes) and `.github/` (CI on every push, a release on every `vX.Y.Z` tag, the test-report issue form). `display_presets.json` stays at the repository root as well, because players fetch it from there.

## [0.8.2] - 2026-11-02

### Fixed

- The preset editor's HTTP API on port 4567 took file names and paths from the request as given: a backup name could point outside the backups directory (download, delete, upload, restore) and import-from-path read any JSON file on the device. Both now accept a bare `.json` file name, or a path under `/data`, `/mnt`, `/media` or `/home/volumio`, only.
- Import from URL in the preset editor always failed (it called a function that did not exist). It works: http or https, 30 seconds, 10 MB.
- Preset ids are limited to letters, digits, dot, dash and underscore; the translations route accepts language codes only.

### Removed

- The `Access-Control-Allow-Origin: *` header on the preset editor's API; the page is same-origin and never needed it.

## [0.8.1] - 2026-03-24

The plugin as the Volumio store ships it, the starting point of this repository's rework.

- HDMI (single and dual), DSI, DPI and composite outputs on Raspberry Pi 2 to 5 and Compute Modules, written to `/boot/videoconfig.txt` and `/boot/cmdline.txt`, with the display lines of `/boot/volumioconfig.txt` moved out of the way.
- A presets database of 197 screens (Waveshare, Raspberry Pi, Elecrow, Adafruit, BIGTREETECH, Hosyond, LCDwiki and others) with a remote update channel, and a preset editor served on port 4567.
- A first-run wizard, rotation, KMS/CMA settings, migration of existing display settings, detection of configuration drift after a system update with restore, backups and restore points.
- Six languages: English, German, Spanish, French, Italian, Dutch.
